# Qiita Drafts

Qiita 記事の下書き＆ネタストック置き場。

## 📁 構成

```
qiita-drafts/
├── README.md                          # このファイル
├── ideas.md                           # ネタ一覧（書きたいテーマのストック）
└── YYYY-MM-DD-slug.md                 # 個別の記事下書き
```

## 🔄 運用フロー

1. **ネタが浮かんだら** → `ideas.md` に追加（カテゴリ別）
2. **書く日が来たら** → `ideas.md` から1つ選んで個別ファイル化
   - ファイル名: `YYYY-MM-DD-slug.md`（例: `2026-04-24-server-component-hydration.md`）
3. **執筆 → 推敲 → Qiita 投稿**
4. **公開後** → `ideas.md` のステータスを `published` に更新、公開 URL を追記

## 📝 記事フォーマット（推奨）

各記事の冒頭にメタ情報を書く：

```markdown
---
status: draft | in-progress | published
target: 想定読者
tags: Next.js, React, Zod, ...
published_url: (公開後に追記)
---

# タイトル

...
```

## 🎯 投稿方針

- **1日1記事ペース**で継続
- 学習中に詰まったポイント・気づきを素材にする
- 結論先出し、コードと解説のセット
- 「なぜそうするか」を明示
- 体験ベース＋一般化、の構成

## ✍️ スタイルガイド（記事執筆時のルール）

### マークダウン記法
- **H2（`##`）の上に区切り線（`---`）は入れない**
  - H2 自体が区切りとして機能するため不要
  - Qiita の見た目を整える意図で挿入しがちなので注意
- 区切り線は「メタ情報の枠（frontmatter）」と「参考リンクの前」など、明確な区切りが必要な箇所のみ

### 文体
- 「ですます調」基本
- 大阪弁は読み手を選ぶので、推敲時に標準語に直す
- 親しみやすさは出すが、読みづらくならない範囲で
